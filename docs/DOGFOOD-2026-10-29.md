# Village Rewards: village rehearsal, 29 October 2026

## Current readiness

Use https://tinyforests.github.io/villagerewards-staging/ . This is an isolated test environment. Do not use the production points app for this rehearsal.

Automated checks passed on 28 October: seven ledger cases, legacy activity checks, syntax checks and local browser flow covering award, lost-response retry, claim, cancellation, collection, retained balance, keyboard, mobile layout and logout. The browser test uses a local SQL database with stubbed authentication and network; it does not certify the deployed flow or physical camera.

The customer claim now includes a collection QR and a manual code fallback. Actual phone-to-phone scanning still needs verification.

Blocking setup: custom SMTP with a verified sender domain, Bruce’s sign-in, a test shop and explicitly assigned retailer account. Tyson’s email verification and successful mobile sign-in were confirmed on 26 October; the mobile dashboard has not yet been independently checked.

## Before meeting

- Bring two charged phones with mobile data. Keep customer and retailer signed into different accounts.

## Walk-through (about 20 minutes)

1. Customer signs in from the emailed link and sees zero stamps, the test shop and the test reward.
2. Customer opens Show my code. Retailer scans it, enters receipt TEST-001, confirms and awards one stamp. Customer refreshes or waits 15 seconds: balance 1.
3. Repeat TEST-001: balance stays 1. This tests duplicate protection.
4. Award TEST-002 and TEST-003: balance 3.
5. Customer claims the 2-stamp reward: available balance 1, reserved 2, stock falls from 3 to 2.
6. Customer cancels: balance 3 and stock 3. Claim again: balance 1.
7. Retailer scans the collection QR, checks terms and confirms handover. Customer keeps 1 stamp. Reusing the collection code must not hand out another reward.
8. Reverse TEST-003: balance 0. Retry reversal: no second deduction.
9. Pause the offer: it disappears from new claims. Republish it.
10. Deny camera permission and try manual code entry. Close scanner and reopen it. Check both customer and collection codes.
11. Turn off mobile data before an award; verify an error, reconnect and retry the same receipt. Only one stamp may be awarded.
12. Log out, reload and sign back in. Account data must be hidden while signed out and restored only after authentication.

For cross-shopping, add a second explicitly authorised test shop and verify stamps earned there can redeem the first shop’s reward. Record expiry restoration after 15 minutes and simultaneous last-stock claims separately; neither is certified by the local browser test.

## Record each result

Record device/browser, action, expected outcome, actual outcome and any screenshot. Never record login tokens or emailed sign-in links. Stop testing real rewards if balances, stock or collection outcomes disagree.

## Public launch gates

Email delivery and real separate-account acceptance must pass. Confirm participating businesses, reward stock, customer terms/privacy, refund rules, support owner, recovery plan and legacy-points transition before a public cutover. Shop-specific loyalty cards, prize draws and the new analytics dashboard are not implemented in this candidate. A successful rehearsal is not approval to promise those features.
